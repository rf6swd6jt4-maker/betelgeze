# Independent draft-recovery and CI review

Read-only application review performed in the isolated consolidation worktree on 23 September 2026. The navigation owner implemented the draft fixes. The reviewer implemented only the separately authorized CI corrections after reporting them. No production operation, provider call, browser operation, commit or application-runtime edit was performed by this review.

## Findings resolved

1. **Preserved account was incorrectly stopped.** `activateOfflineAccount` dispatches `betelgeze:offline-account-clearing` with the newly authenticated actor as `preservedUserId`. The new text/form journal listeners originally stopped unconditionally, disabling a newly mounted matching actor until remount. All three new listeners now honor the matching preserved actor; displaced/unspecified actors checkpoint and stop or close recovery. Independent execution of the exact callbacks verified each event case for the hook, form and recovery dialog.
2. **Stopped recovery owner could reopen old copies.** Closing an existing dialog on account clearing did not prevent its still-mounted button reopening the inactive journal. Recovery now checks active ownership before opening and before accepting an asynchronous review result, as well as before restore. The independent callback probe verifies both refusal to reopen and discarding a late result. No journal was deleted to fix the issue.
3. **Local CI gate could hide staged bytes.** A temporary-Git reproduction staged a historical SQL edit, restored baseline working bytes, and received an empty issue list. The gate now refuses a path with both staged changes and different working bytes, including a staged deletion restored as untracked. Ordinary entirely unstaged edits and fully staged files retain the same lint scope. Four behavioral temporary-Git regressions cover the fix. The SQL CI job also now writes JSON under the runner temporary directory and prints actual runtime/version/source metadata, rather than discarding that evidence.

The integrator's earlier fix for selecting recovery during an in-flight save was also reviewed: restoration pauses automatic flush; the old acknowledgement may reconcile its own baseline but cannot automatically submit the recovered copy. Explicit “Save reviewed draft” is required. The actual-hook regression passed in this independent run; the reviewer did not discover or implement that earlier correction.

## Remaining boundaries

Scope includes user/workspace/type/record/field; fresh writer IDs keep separate tabs from overwriting or acknowledging each other's copies. Recovery archives current intent before applying a selected copy, and imported/corrupt entries are not deleted. This establishes source/test behavior, not production interaction latency, physical-device lifecycle guarantees, authenticated permissions or provider behavior.
