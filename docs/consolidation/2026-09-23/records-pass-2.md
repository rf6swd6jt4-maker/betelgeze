# Records, notes and attachments: Pass 2 implementation evidence

This package is local implementation in `/private/tmp/betelgeze-platform-consolidation`. No production SQL, storage operation, provider configuration, browser operation, deployment or client-data write was performed. The production schema/application/provider acceptance gates remain open. A successful local build or fixture is not proof of installed schema, authenticated UI or real R2 behavior.

## Resulting contracts

- **A1:** `20260923170000_note_attachment_integrity.sql` replaces the defective shared note-link trigger with separate table branches. It preserves trigger bindings, workspace checks, keys and existing rows. Historical migrations are unchanged. Prior isolated evidence reproduced both original row-shape failures and passed 13 corrected-trigger checks; root separately matched the original production function hash.
- **A2:** attachment cards and picker choices have separate bounded request owners. Requests deduplicate within their mounted scope, expire after 30 seconds including JSON parsing, abort on scope/activity changes and discard late results/errors. Retry is explicit. The retained cache contains at most 30 record scopes and retains the incoming cursor with its page, including the last page. A confirmed link is shown as linked even when its optional refresh fails. The gallery and picker page assets and notes independently (20 of each, with one lookahead row per lane); choices use explicit server search. No full-library preload or all-library image signing is added.
- **A3 notes:** field commands compare the edited field against its baseline while holding the note row lock. Different fields can save independently; same-field conflicts retain the local draft through the existing text-draft owner. Relationship commands apply explicit additions/removals from the selection baseline; unseen concurrent links survive. Old whole-form commands fail visibly without writing. Every command checks active workspace/admin membership in SQL as well as application authorization and submitted actor identity.
- **A3 uploads:** new manual assets use a signed receipt binding workspace, actor, request, exact path, size, type, name and expiry. New paths are `workspace/assets/actor/request/original`; legacy stored paths/read authorization remain unchanged. Signed PUT requires `If-None-Match: *`, content type and content length. After upload, a bounded 15-second HEAD checks size/type/ETag before first creation. A receipt for another actor, workspace or path is rejected. No COPY, overwrite, cleanup deletion or historical asset migration is used. The only shared CORS source change is the additive `if-none-match` allowed header; existing rules/encryption headers are preserved by a mocked runtime test.
- **A4:** `20260923171000_record_attachment_commands.sql` creates service-only commands and durable request receipts. A workspace/actor/request advisory lock serializes identical creation intent. Parent, requested links and accepted receipt commit together. Known validation/constraint failures roll back the parent/link subtransaction and commit a terminal rejected receipt. A delayed retry of that rejected ID cannot later create a record, even if its target becomes valid. Accepted replay returns the original ID before revalidating later target archival or upload expiry. Authorization failures remain outside terminal rejection; transport/schema/internal errors are never treated as proof of non-commit.
- **Draft recovery:** before create RPC dispatch, scalar intent and receipt are stored under a separate actor/workspace/context/request key; file bytes are not persisted. Independent tabs cannot overwrite or acknowledge each other's request entries. Recovery parses every matching entry before enabling a new submit; storage/corruption errors block submission without discarding data. Unknown outcomes retain the exact request for Retry. The form is frozen while restoration is unresolved or a request is pending, with the saved name/description shown; new visible typing cannot be silently discarded by replaying older intent. Only an authoritative terminal rejection offers explicit Edit saved draft; text/selections are restored, the old terminal request remains checkpointed until replacement intent is stored, and assets require selecting their file again. Accepted replay clears only its matching saved value. Multiple pending entries are recovered one at a time on reopening the corresponding create context.

## Provider evidence boundary

Cloudflare documents conditional `If-None-Match` for PutObject in its [R2 S3 compatibility table](https://developers.cloudflare.com/r2/api/s3/api/) and the failed-condition `412` behavior in its [release notes](https://developers.cloudflare.com/r2/platform/release-notes/). Its [presigned URL documentation](https://developers.cloudflare.com/r2/api/s3/presigned-urls/) describes signed-header matching. A local test uses the installed AWS SDK with fixture credentials and an invalid endpoint to verify `X-Amz-SignedHeaders` includes `if-none-match`, `content-type` and `content-length`; it sends no request. Live R2 conditional/CORS behavior, actual upload/HEAD latency and browser header behavior remain unverified. No provider credential or live object was used as a fixture.

## Rollback and limits

Rollback the application callers first if required, retaining the additive table, receipts, functions, fixed trigger and stored objects. Do not drop terminal receipts, remove accepted records, erase local recovery entries, or revert to the defective trigger to make rollback appear clean. A prior application build with blind note replacement/sequential creation would reintroduce the audited defects; disable those writes or retain the guards in any rollback build.

No generic upload helper, onboarding upload contract, SOP ingestion pipeline, message-media authorization, sales/service snapshot, provider outbox or client history was migrated. Unsubmitted browser File bytes are not recoverable across browser termination; the durable create checkpoint starts after upload and before record mutation. Orphaned synthetic/new uploads after a failed create are retained, not garbage-collected. Damaged/tampered receipt drafts and revoked authorization remain blocked for deliberate support/recovery; they cannot silently rotate into new create requests. Existing create-modal option lists outside the attachment picker retain their existing bounded-choice behavior; the new exhaustive paging/search contract belongs to Add > Pick existing. Rendered accessibility, authenticated UI, real storage conditional behavior and live performance remain release gates, not local-test claims.
