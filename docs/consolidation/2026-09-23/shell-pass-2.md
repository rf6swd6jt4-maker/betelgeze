## Status at the earlier checkpoint

**Local implementation is frozen, with one unresolved release blocker.** The current shell performs its final synchronous draft check before scheduling React state changes. React may defer the actual iframe/native-owner unmount until a later commit. A legacy flush-only owner could receive another input between that check and unmount. The current tests do not prove that interval safe. Do not promote this shell package as complete draft-loss protection while this gap remains.

The proposed same-task commit repair is preserved, unapplied, in [proposed-shell-commit-wrapper.patch](./proposed-shell-commit-wrapper.patch). It changes the returned confirmation into a callback accepting the destructive operation, validates and runs that operation inside `flushSync` only when an existing frame/native owner is displaced, and wraps speculative eviction similarly. Owner-free operations retain their ordinary scheduling. All 10 prepared-departure call sites are represented. The candidate was generated as review text, parsed with TypeScript without syntax diagnostics, and was neither applied nor executed. Its actual React/browser behavior and latency remain unverified.

Independent static review also identified a pre-existing path outside those 10 call sites: `NativeWorkspaceTab.navigate` awaits its own flush, then posts `navigation-start` or `location-replace`. The native branches of the host receiver update `tab.url` without `prepareNativeLeave`. Their native in-panel route/owner replacement therefore also requires a final same-task fence; the proposed patch does not yet cover it. This is an outstanding coverage issue, not a claim that the review-only patch completes every departure path.

## Accepted local changes

- Optional tab/sidebar/context metadata now uses `lib/workspace-shell-storage.ts`. Security/quota/access failures switch that shell lifetime to an in-memory fallback and one bounded diagnostic. Failed removal cannot resurrect a closed key, and the fallback does not retain an unbounded tombstone per closed tab. This helper is not used for drafts or mutation commands; failed draft persistence still refuses departure.
- Closing a tab prunes stable frame IDs, resident IDs, context metadata/state and existing per-tab bookkeeping. The reopen stack remains capped at 20 and retains its context-open preference. The resident cap remains three.
- `lib/workspace-tab-departure.ts` implements a bounded local frame request/acknowledgement, fenced by origin, source window, tab, request and exact document identity. A changed document behind the same WindowProxy cannot authorize departure. Timeout, cancellation, missing receiver on a formerly live page, and false acknowledgements retain the old owner.
- Never-live blank/error documents have explicit no-owner handling. `WorkspaceTabBridge` leaves a document-lifetime page-mounted marker; the additive `ErrorBoundaryReporter` marker exists only while its committed error boundary is mounted. A previously usable page never becomes owner-free merely because its receiver is missing.
- Shell close, Retry, iframe-to-native renderer replacement and capped resident eviction now consult the displaced frame owners. Navigation that fails specifically because draft persistence was denied restores the retained editor and removes its destination overlay. A distinct `WorkspaceFrameDraftError` prevents generic router failures being mislabeled as failed saves.
- Final synchronous confirmation calls the same document's current receiver. Checkpoint owners checkpoint again; legacy flush-only owners must retain their registry generation and have no input/change/click/submit edits since flush began, nor a new mutation intent after acknowledgement. Mutation-intent tracking arms after the acknowledged flush, so a successful flush does not reject its own save. Confirmations are single-use, with bounded listener/timer cleanup. This closes the asynchronous acknowledgement gap, subject to the separate React commit gap above.
- Speculative full-pool warming uses checkpoint-only preflight and final checkpoint confirmation, with no network flush. Owner-free/checkpoint-capable pages still warm. Legacy owners without a synchronous checkpoint, failed storage, missing acknowledgements or changed identity are retained and that speculative warm is skipped. No unbounded resident pool or retry loop was added.
- Rapid A→B→A switching cancels an earlier pending B departure when the user chooses retained A. Account clearing/unmount invalidates outstanding checks. Switch/add/close/history use current tab metadata after awaiting checks, preserving renames and other updates made while waiting.
- Native shell Retry now explicitly resets a failed `PanelBoundary` and invokes its existing read refresh. Ordinary activation refresh preserves the boundary and mounted owner.
- Lead Gen direct-search shortcuts and sidebar version metadata were removed at the quarantine owner's request. The historical poll-start bridge remains compatible.
