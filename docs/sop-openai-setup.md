# OpenAI setup for SOP interpretation

This integration uses the OpenAI API, not a ChatGPT subscription. Keep API keys out of chat, source control, browser code, screenshots and terminal output.

## Development setup

1. Sign in at https://platform.openai.com/ and create a separate project named **Betelgeze Development**.
2. Configure API billing and usage notifications for that project. Choose a small testing allowance. Dashboard notifications are not a reliable hard spending stop.
3. Open the project's API keys and create a secret key named **Betelgeze SOP development**. For restricted credentials, this implementation needs permission to create Responses. It does not use hosted Files, vector stores, external tools, or a ChatGPT login.
4. Open `.env.local` in the Betelgeze repository using your editor. Preserve existing values. Add:

   ```dotenv
   OPENAI_API_KEY=your-secret-key
   OPENAI_SOP_MODEL=gpt-5.4-mini
   SOP_AI_ENABLED=false
   SOP_AI_DAILY_LIMIT=10
   ```

   The repository ignores `.env*`. Never prefix the key with `NEXT_PUBLIC_`. No organization ID, project ID or account password is needed when using a project-scoped key.
5. Tell Codex **configured locally**. Do not send the key. Its presence can be checked without printing its value.
6. After the SOP migration and local app are ready, change `SOP_AI_ENABLED` to `true` and restart the development server. In an SOP, upload one small non-sensitive test document or TXT file and press **Interpret asset**. Upload alone does not call OpenAI.
7. Use **Check interpretation** to read progress. Review the draft against the source before **Mark reviewed**. A completed API call is not proof of accurate extraction.
8. Keep the flag false whenever you want storage/viewing only. The model is configurable; the initial model is a test baseline, not a verified best performer on agency SOPs.

The worker permits at most ten accepted attempts per workspace per UTC day by default, including retries and pending requests. Configuration accepts 1–100. It allows three attempts per source/schema version. Inputs are capped at 20 MiB for interpretation, text at 100,000 characters, and output at 10,000 tokens. These are request/resource bounds, not a guaranteed dollar cap; PDF page complexity, provider tokenization and retries affect charges.

## Production setup and recovery

1. Apply the SOP catalogue migration and `20260914100000_sop_records_and_interpretation.sql` through the normal reviewed release process. This creates records, links legacy documents, and adds the durable interpretation queue.
2. Create a separate **Betelgeze Production** OpenAI project and key. Add its key and the other variables to the server environment in Vercel. Leave the feature disabled while verifying the release. Do not reuse production credentials in preview deployments.
3. Configure the existing job scheduler to request `POST /api/cron/sop-interpretations` with `Authorization: Bearer <CRON_SECRET>` at a bounded interval, such as once per minute. This route accepts GET too. Reuse the server's existing `CRON_SECRET`; never expose it publicly. If no scheduler exists, configure one before enabling production interpretation. This code change does not provision a scheduler or a paid hosting plan.
4. The initial request persists its job before responding and wakes a worker using Next.js `after`. The recovery endpoint is necessary because that wake-up is not itself durable. **Resume interpretation** also wakes an already queued job without reserving another attempt.
5. Each worker invocation claims at most one job with a six-minute lease and a maximum route duration of 300 seconds. Verify the deployed host supports that duration. An interrupted running job becomes failed after its lease expires; it is never automatically charged again. An admin may explicitly retry, consuming another reserved attempt.
6. Verify real R2 upload, signature checks, staff viewing, admin authorization, large-file playback, worker wake-up, scheduled recovery, access revocation, and provider output before enabling live use. Keep a test fixture with external delivery disabled.
7. To roll back interpretation, set `SOP_AI_ENABLED=false`. No work items are generated by this implementation. Existing SOPs, assets and interpretations remain readable; running provider requests may already have incurred usage.

## What the interpreter currently reads

- PDF: provider file input, including document visuals where supported.
- DOCX, PPTX, XLSX: provider file input; embedded visuals/layout may be omitted. Upload a PDF or separate images when those carry instructions. Spreadsheet extraction should not be assumed exhaustive.
- TXT, Markdown and CSV: bounded UTF-8 text. Returned source quotes are checked against that text.
- PNG, JPEG, WebP and GIF: image input; provider restrictions such as animated images can cause a visible failure.
- Video/audio: stored for playback/download. Automatic transcription and visual video interpretation are not implemented. Attach a transcript as TXT/PDF and relevant screenshots.

Each draft records its source hash, model, schema/prompt version, usage, and review state. Documents and notes cannot grant tools or trigger external actions. Non-text source quotes and locations require human verification. No source is automatically approved and no work plan is generated.

`store: false` avoids storing the response as application state through that option; it does not promise zero retention across all provider systems. Review your selected settings against OpenAI's data controls before sending sensitive sources.
